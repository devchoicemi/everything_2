# ChoiceMi Mobile

A [Capacitor](https://capacitorjs.com) native wrap of `web/` — **not** a
separate app or a second implementation of the product. Per the root
[`README.md`](../README.md): `mobile/` = "PWA / Play Store wrap of `web/`".

## Why a wrap, and not a rewrite

Every screen, the self-vs-ideal compatibility engine, the profile-reading
verification gate and the "no messaging, 12pm–7pm only" propose-a-date rules
already exist as a real, tested Next.js app in `web/`. Rebuilding that in
React Native/Flutter/etc. would mean maintaining the scoring logic, the gate's
attempt/block/cooldown state machine and every screen in two places — a
correctness risk this pilot doesn't need. Instead:

- **`android/` and `ios/`** are real native projects (generated by
  `npx cap add android|ios`) — buildable, store-submittable apps.
- At runtime, the native shell loads `web/`'s live URL into a WebView
  (`capacitor.config.ts` → `server.url`). A fix or new screen shipped to
  `web/` reaches mobile users the next time they open the app — no store
  resubmission.
- Native-only capability (push notifications, native splash/status bar,
  app store presence, deep links) is added here, on top.

## Layout

```
mobile/
├── android/            Native Android project (Gradle) — generated, mostly hands-off
├── ios/                 Native Xcode project — generated, mostly hands-off
├── assets/              Icon/splash SOURCE images → run `npm run assets` to regenerate
│                         the platform-specific files under android/ and ios/
├── www/                  Offline-fallback shell only (shown if server.url is unreachable) —
│                         NOT the app UI; that's all in ../web
├── capacitor.config.ts  server.url (where the WebView points), app id, branding
└── package.json
```

## Prerequisites

| Target  | Needs |
| ------- | ----- |
| Android | [Android Studio](https://developer.android.com/studio) (provides the SDK + an emulator) |
| iOS     | Xcode, **macOS only** — cannot be built or run on Windows/Linux |

This environment (Windows, no Android SDK/Xcode installed) could scaffold
the projects but cannot build or run them. Everything below needs one of the
above installed first.

## Dev workflow

1. Run the web app: `cd ../web && npm run dev` (http://localhost:3000).
2. Point the wrap at it:
   - **Android emulator** — already defaults to `http://10.0.2.2:3000`
     (the documented alias for the host machine's `localhost` from inside
     the emulator). Nothing to change.
   - **Physical device / iOS simulator** — set `CHOICEMI_WEB_URL` to your
     machine's LAN IP, e.g. `CHOICEMI_WEB_URL=http://192.168.1.50:3000`,
     since the device can't resolve `10.0.2.2` or `localhost`.
3. `npm run sync` — copies `capacitor.config.ts` and the `www/` fallback
   into the native projects. Re-run this after any config change.
4. `npm run open:android` / `npm run open:ios` — opens Android Studio /
   Xcode. Run from there (▶) onto an emulator/simulator or a connected
   device. (`npm run run:android` / `run:ios` also works once a device or
   emulator is already running, without opening the IDE.)

## Before a real store build

- Point `capacitor.config.ts` at the production URL:
  `CHOICEMI_WEB_URL=https://<production-domain> npm run sync`, or edit the
  fallback default directly.
- Regenerate icons/splash if `assets/*.png` change: `npm run assets`.
- Android: set a real `applicationId`/signing config in
  `android/app/build.gradle` before a Play Console upload (currently
  `fi.choicemi.app`, debug-signed).
- iOS: set the bundle id/signing team in Xcode before a TestFlight/App
  Store upload.

## iOS + local HTTP dev server

App Transport Security blocks plain `http://` by default on iOS (Android's
debug-only cleartext override is already set up in
`android/app/src/debug/AndroidManifest.xml`, applied automatically). To test
against a local dev server on iOS, either tunnel it over HTTPS (e.g.
`npx ngrok http 3000` and point `CHOICEMI_WEB_URL` at the `https://` ngrok
URL) or add a scoped ATS exception for your dev host in
`ios/App/App/Info.plist` before running — don't leave a blanket exception in
place for a store build.

## Not yet wired here

- Push notifications (`@capacitor/push-notifications` + a real Firebase
  project — same FCM gap flagged in `web/README.md`'s pilot follow-ups)
- Deep links (`choicemi://…`) for match/date notifications to open the
  right screen
- Real signing keys for either platform (both are currently debug-only)
- `mobile/capacitor.config.ts`'s production fallback URL needs to track
  wherever `web/`'s `main` branch actually deploys — confirm that's current
  before pointing a store build at it (see `web/`'s own PR/deploy status)

## Already wired

- Native app icon + adaptive icon (Android) + splash screen, generated from
  `assets/*.png` via `npm run assets` — matches web's teal brand mark
  exactly, no separate design work
- Status bar and splash screen theming (`@capacitor/status-bar`,
  `@capacitor/splash-screen`, configured in `capacitor.config.ts`) — dark
  teal background, no white flash before the WebView paints
- `@capacitor/app` (installed, not yet called from anywhere — available for
  back-button handling / deep-link routing when that's built)
